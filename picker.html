Receives image bytes and optional PickerConfig. Pillow applies EXIF orientation, handles alpha, and converts to RGB. Trimming and encoding produce image bytes, dimensions and coordinate-remapping metadata.

def normalize_screenshot(image_bytes: bytes, config: PickerConfig | None = None, *, maximum_edge: int | None = None) -> PreparedScreenshot:
    config = config or PickerConfig()
    if len(image_bytes) > config.maximum_upload_bytes:
        raise ValueError("Screenshot exceeds the configured maximum upload size")
    started = time.perf_counter()
    try:
        with Image.open(BytesIO(image_bytes)) as source:
            oriented = ImageOps.exif_transpose(source)
            if "A" in oriented.getbands():
                alpha_box = oriented.getchannel("A").getbbox()
                oriented = oriented.crop(alpha_box) if alpha_box else oriented
            original = oriented.convert("RGB").copy()
    except (UnidentifiedImageError, OSError, ValueError) as exc:
        raise ValueError("The screenshot could not be decoded as an image") from exc
    trimmed, trim_box = _safe_trim(original)
    normalized_bytes, normalized_size = _encode(trimmed, maximum_edge or config.maximum_normalized_edge, config.normalization_quality)
    return PreparedScreenshot(original, trimmed, trim_box, normalized_bytes, normalized_size, round((time.perf_counter() - started) * 1000))
Bound concurrent extraction python

In plain language

The SDK processes several screenshots together while limiting simultaneous extraction calls.

Inputs, outputs and control flow

Receives a bulk request, configuration and injected dependencies. A semaphore guards each async extraction. asyncio.gather collects results in input order and propagates errors.

Design, integration and security

Injected provider dependencies let tests avoid live API calls. Bounding active work does not bound the number of scheduled tasks or guarantee provider quota compliance. The host must control inputs and cancellation.

Testing and verification

tests/test_picker.py exercises bounded bulk concurrency with injected dependencies.

Potential improvements

For large batches, consider a worker queue and explicit per-item outcomes.

async def extract_screenshots_bulk(request: PickerBulkExtractionRequestV1, *, config: PickerConfig | None = None,
                                   dependencies: PickerDependencies | None = None) -> list[PickerExtractionResultV1]:
    config = config or PickerConfig(); dependencies = dependencies or PickerDependencies()
    semaphore = asyncio.Semaphore(config.concurrency_limit)
    async def run(item):
        async with semaphore:
            return await extract_screenshot(request=item, config=config, dependencies=dependencies)
    return await asyncio.gather(*(run(item) for item in request.requests))

The Swift prototype reads text from an image on the device and returns its location in the image.

The actor accepts Data, uses ImageIO and Vision, and returns recognized text, confidence and normalized bounding boxes. Invalid images throw unsupportedImage. Task cancellation attempts to cancel the Vision request.

Actor isolation keeps work off the main actor. Orientation is read from the image metadata. The excerpt performs no network request. Cancellation checks surround synchronous Vision processing.

Testing and verification

Potential improvements

actor LocalOCRService {
    func recognize(_ data: Data) async throws -> [RecognizedTextItem] {
        try Task.checkCancellation()
        guard let source = CGImageSourceCreateWithData(data as CFData, nil),
              let image = CGImageSourceCreateImageAtIndex(source, 0, nil) else {
            throw LocalOCRError.unsupportedImage
        }
        let properties = CGImageSourceCopyPropertiesAtIndex(source, 0, nil) as? [CFString: Any]
        let rawOrientation = (properties?[kCGImagePropertyOrientation] as? NSNumber)?.uint32Value ?? 1
        let orientation = CGImagePropertyOrientation(rawValue: rawOrientation) ?? .up
        let request = VNRecognizeTextRequest()
        request.recognitionLevel = .accurate
        request.usesLanguageCorrection = true
        return try await withTaskCancellationHandler {
            try Task.checkCancellation()
            try VNImageRequestHandler(cgImage: image, orientation: orientation).perform([request])
            try Task.checkCancellation()
            return (request.results ?? []).compactMap { observation in
                guard let candidate = observation.topCandidates(1).first else { return nil }
                let box = observation.boundingBox
                return RecognizedTextItem(
                    text: candidate.string,
                    confidence: candidate.confidence,
                    boundingBox: TextBoundingBox(x: Double(box.minX), y: Double(box.minY),
                                                width: Double(box.width), height: Double(box.height))
                )
            }
        } onCancel: {
            request.cancel()
        }
    }
}

Overview and problem

Picker converts screenshots and recordings into structured evidence for other applications. It gives host systems a reusable way to capture visible fields, content crops, and provenance before they make domain decisions.

Architecture and integrations

The Python package uses Pydantic contracts, Pillow image processing, HTTPX provider adapters, and local FFmpeg tools. Screenshot requests can use a configured OpenAI vision provider. Recording analysis samples frames and groups likely candidates. The separate SwiftUI and Vision iOS prototype explores local OCR.

Implemented capabilities and safeguards

Picker supports individual and bulk screenshot workflows, exact and perceptual hashes, configurable fallback, and bounded recording analysis. The consuming application owns access, persistence, and review. Provider-backed extraction sends image data to the configured provider. Recording candidates and recognized fields remain subject to review.

Engineering challenge

Screenshots and recordings can contain duplicate frames, transient overlays, and incomplete context. The extraction contract carries confidence and provenance so the host can review uncertain results.

Validation and roadmap

Thirty-three Python tests passed with synthetic inputs and external socket connections blocked. An iOS structural check passed. Swift compilation, XCTest, signing, and device behavior remain unverified. Future work includes iOS acceptance testing, broader cleared test data, and reproducible package releases.
