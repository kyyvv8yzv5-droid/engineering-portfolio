In plain language

When the evidence pipeline cannot apply its policy, the result explicitly says that the decision is inconclusive.

Inputs, outputs and control flow

Accepts an error reason. Builds a FusionResult with neutral scores, zero confidence and no contributions, then adds the compatibility fields consumed by callers.

Design, integration and security

The engine keeps the public response shape even when policy or inputs are invalid. The neutral score is a sentinel and should not be interpreted as a calibrated probability. Fusion weighting and model configuration are omitted.

Testing and verification

tests/test_fusion.py exercises fusion policy and response behavior. The source snapshot passed 472 Python and 28 JavaScript tests.

Potential improvements

Use a stable error code for clients while limiting potentially sensitive diagnostic detail at the API boundary.

Overview and problem

AuthenticityAI is a local research platform for evaluating media authenticity signals. It addresses the need to inspect heterogeneous evidence while keeping provenance, detector availability, and uncertainty visible to reviewers.

Architecture and integrations

A Python and FastAPI service hosts an operator UI and an isolated showcase. OpenCV and MediaPipe support analysis, SQLite and a managed filesystem hold local state, and a fusion layer combines detector evidence. Separate acquisition, training, and evaluation workflows use governed dataset sources. The research path includes optional learned detector adapters and an offline CNN baseline.

Implemented capabilities and safeguards

The platform supports media analysis, provenance review, duplicate handling, dataset acquisition, controlled splits, and evidence reports. Local authentication and role checks separate operators from showcase access. Detector failures and insufficient evidence remain explicit. The model research described here does not establish commercial decision accuracy.

Engineering challenge

Detector outputs have different reliability and availability. The system needs to preserve provenance and uncertainty through normalization, evidence fusion, and reporting.

Validation and roadmap

The source-only snapshot passed 472 Python and 28 JavaScript tests with disposable SQLite data and the OpenCV fallback. External research data and learned weights were outside this verification.
